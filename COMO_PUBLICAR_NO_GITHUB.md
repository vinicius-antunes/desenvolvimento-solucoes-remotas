# Como publicar os arquivos no seu GitHub

Os arquivos estão prontos para um repositório, mas **nenhum repositório foi criado ou configurado automaticamente**.

1. No GitHub, clique em **New repository**.
2. Escolha um nome, por exemplo, `desenvolvimento-solucoes-remotas`.
3. Selecione a visibilidade conforme a orientação do professor (público ou privado). Se for necessário que ele leia sem pedir acesso, normalmente o repositório público é mais simples.
4. Para publicar estes arquivos, você pode criar o repositório **sem adicionar README inicial** e usar **Add file → Upload files**.
5. Extraia o ZIP no seu computador e envie o conteúdo da pasta `atividade_solucoes_remotas_github` (as pastas `atividades`, `materiais`, `projeto-integrador` e os arquivos `.md`). Preserve essa estrutura.
6. Clique em **Commit changes** e confirme se o `README.md` aparece na página inicial do repositório.
7. Copie o endereço do repositório e encaminhe ao professor **pelo canal solicitado**.

## Atenção aos formulários pós-aula

Pelas orientações informadas, os links dos formulários serão divulgados após as aulas. **Verifique o formulário e suas instruções antes da entrega**: o professor não especificou aqui se o link do GitHub deve ser colado no formulário, se há campos adicionais ou se algum sistema publicará os envios no GitHub automaticamente.

## Estrutura recomendada

```text
desenvolvimento-solucoes-remotas/
├── README.md
├── atividades/
│   ├── 01-unidade-iv-usabilidade.md
│   ├── 02-unidade-v-redes.md
│   ├── 03-unidade-vi-projeto-integrador-questoes.md
│   └── gabarito-resumido.md
├── materiais/
│   └── 50_questoes_desenvolvimento_solucoes_remotas.pdf
└── projeto-integrador/
    └── README.md
```

Se o professor exigir uma atividade pós-aula diferente, acrescente um arquivo separado em `atividades/` com identificação clara da data e do tema, sem substituir as questões de revisão.
